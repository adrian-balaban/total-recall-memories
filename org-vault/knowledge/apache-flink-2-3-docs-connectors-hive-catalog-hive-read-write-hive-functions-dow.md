## Source: .../table/hive/hive_catalog/ — Hive Catalog
Hive Metastore = de facto metadata hub in Hadoop ecosystem. For users with Hive+Flink: HiveCatalog uses Hive Metastore to manage Flink metadata. For Flink-only users: HiveCatalog is the only persistent catalog out-of-box (without it, CREATE DDL meta-objects like Kafka tables must be re-created each session).
### Set up: same deps + configuration as overall Flink-Hive integration.
### How to use: works out of box. Two table kinds: Hive-compatible tables (stored Hive-compatible in metadata+storage; queryable from Hive) and generic tables (Flink-specific; HMS persists metadata; visible to Hive but Hive likely can't understand → undefined behavior). Recommended: switch to Hive dialect for Hive-compatible tables; with default dialect set 'connector'='hive' in table properties else generic (not required with Hive dialect).
### Example (5 steps): (1) set up Hive Metastore (local hive-site.xml /opt/hive-conf) `[code: ... (1158 chars)]`, test via Hive Cli. (2) start SQL Client, add Hive deps to /lib, CREATE Hive catalog `[code: ... (99 chars)]`. (3) bootstrap local Kafka cluster with topic "test", produce name/age tuples. (4) create Kafka table with Flink SQL DDL `USE CATALOG myhive;` `[code: ... (399 chars)]`, verify visible to Hive. (5) run Flink SQL select from mykafka; produce more Kafka messages → see results.
## Supported Types: HiveCatalog supports all Flink types for generic tables. For Hive-compatible tables, Flink→Hive type mapping [table: 18 rows]. Notes: Hive CHAR(p) max 255; VARCHAR(p) max 65535; Hive MAP only primitive keys (Flink any); Hive UNION not supported; Hive TIMESTAMP precision 9 only (UDFs handle ≤9); Hive doesn't support Flink TIMESTAMP_WITH_TIME_ZONE/TIMESTAMP_WITH_LOCAL_TIME_ZONE/MULTISET; Flink INTERVAL can't map to Hive INTERVAL yet.

## Source: .../table/hive/hive_read_write/ — Hive Read & Write
Using HiveCatalog, Flink does unified BATCH + STREAM processing of Hive tables (more performant alternative to Hive batch engine, or continuous read/write for real-time data warehousing).
## Reading: BATCH (query over table state at query time) + STREAMING (monitor table, incrementally fetch new data). Bounded by default. Streaming supports partitioned + non-partitioned: partitioned → monitor new partitions; non-partitioned → monitor new files in folder. [table: 6 rows]. SQL Hints apply config without changing metastore definition `[code: ... (131 chars)]`. Notes: monitor strategy scans all dirs/files (many partitions → perf degradation); non-partitioned streaming requires atomic file writes; partitioned streaming requires atomic partition add in HMS (else new data in existing partition consumed); streaming reads don't support watermark grammar (no window operators).
### Reading Hive Views: Flink reads Hive views with limits: Hive catalog must be current catalog (tableEnv.useCatalog / USE CATALOG); Hive+Flink SQL differ in syntax (reserved keywords, literals) — ensure view query compatible with Flink grammar.
### Vectorized Optimization upon Read: auto-enabled when format ORC/Parquet AND no complex types (List/Map/Struct/Union). Disable: `table.exec.hive.fallback-mapred-reader=true`.
### Source Parallelism Inference: default infers optimal parallelism from #files + #blocks. Configurable in TableConfig (affects all sources) [table: 3 rows].
### Tuning Split Size: splits = data portion consumed by source; tune via configs [table: 3 rows]. NOTE: Flink gets all files' size for all partitions first (many partitions → time-consuming; configure table.exec.hive.calculate-partition-size.thread-num default 3); split-size tuning only works for ORC.
### Read Table Statistics: if stats unavailable from HMS, Flink scans table; configure table.exec.hive.read-statistics.thread-num (default = available processors, must be >0).
### Load Partition Splits: multi-thread split; table.exec.hive.load-partition-splits.thread-num (default 3, >0).
### Read Partition With Subdirectory: external table referring to another table with coarser partition columns → sub-directories in partition dir. Flink recursively scans sub-directories by default (table.exec.hive.read-partition-with-subdirectory.enabled true). Set false to disallow (if dir has no files only subdirs → IOException "Not a file").
## Temporal Table Join: Hive table as temporal table, stream correlates via temporal join. Supports processing-time temporal join (always latest version); supports partitioned (auto-tracks latest partition) + non-partitioned. NOTE: no event-time temporal join yet.
### Temporal Join The Latest Partition: partitioned table read as unbounded stream; partition = version; Flink auto-tracks latest partition via 'streaming-source.partition-order'. STREAMING mode only. Demo: dimension table from Hive updated daily + Kafka stream enriched by join `[code: ... (1995 chars)]`.
### Temporal Join The Latest Table: Hive table as bounded stream; tracks latest version at query time; cached in Slot memory. Optional cache TTL [table: 2 rows]; after expiry re-scanned. Notes: each joining subtask keeps own cache (Hive table must fit TM task slot memory); set large streaming-source.monitor-interval (latest partition) or lookup.join.cache.ttl (all partitions); loads whole Hive table on cache refresh (no new-vs-old differentiation).
## Writing: BATCH (records visible only when Job finishes; supports append + overwrite) `[code: # INSERT INTO ... (297 chars)]`, static partition insert `[code: ... (462 chars)]`. STREAMING (continuously add, commit incrementally; NO insert overwrite for streaming). Demo Kafka→Hive with partition-commit `[code: ... (907 chars)]`; TIMESTAMP_LTZ watermark + partition-time commit requires sink.partition-commit.watermark-time-zone = session time zone `[code: ... (1086 chars)]`. Default streaming uses renaming committers (S3 can't support exactly-once); exactly-once to S3 via config false → Flink native writers (parquet/orc only) [table: 2 rows].
### Dynamic Partition Writing: users don't specify partition column value `[code: INSERT INTO TABLE fact_tz PARTITION (day, hour) select ... (75 chars)]`. Default sorts data by dynamic partition columns before writing (reduces partition writers, improves perf, avoids OutOfMemory). Disable via table.exec.hive.sink.sort-by-dynamic-partition.enable=false (may OOM if many partitions on same sink node). Relieve: DISTRIBUTED BY <partition_field> (shuffle same partition → same node); SORTED BY <partition_field> (same as enable=true). NOTE: enable config only BATCH mode; DISTRIBUTED BY/SORTED BY only Hive dialect BATCH mode.
### Auto Gather Statistic: default gathers stats + commits to HMS during write. Disable via table.exec.hive.sink.statistic-auto-gather.enable=false. Parquet/ORC → numFiles/totalSize/numRows/rawDataSize; else only numFiles/totalSize. numRows/rawDataSize for Parquet/ORC via file footer (fast); many files → table.exec.hive.sink.statistic-auto-gather.thread-num (default 3). NOTE: only BATCH mode.
### File Compaction: Stream mode = same as FileSystem sink. Batch mode: if avg written file size < threshold → compact to target size [table: 5 rows].

## Source: .../table/hive/hive_functions/ — Hive Functions
## Use Hive Built-in Functions via HiveModule: HiveModule provides Hive built-in functions as Flink system functions. Java/Scala/Python/SQL Client examples (`LOAD MODULE hive WITH ('hive-version' = '2.3.4');`). Some older Hive built-in functions have thread safety issues — patch own Hive.
## Use Native Hive Aggregate Functions: if HiveModule higher priority than CoreModule, Flink uses Hive built-in first; Hive built-in aggregation functions only use sort-based aggregation operator. From Flink 1.17 native hive aggregation functions (sum/count/avg/min/max) use hash-based aggregation operator — enable table.exec.hive.native-agg-function.enabled [table: 2 rows]. Attention: native agg doesn't fully align with Hive built-in (some data types unsupported); can't be turned on per job via SqlClient (module level only — turn on first then load HiveModule).
